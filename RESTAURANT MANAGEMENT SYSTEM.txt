1. INTRODUCTION
A restaurant is a service-oriented environment in which several activities occur simultaneously. Customers select food from a menu, place orders, wait for preparation, receive their food, and finally complete payment. At the same time, staff members need to monitor tables, food availability, order status, and sales.
A software-based Restaurant Management System can organize these activities. In this project, Java is used to create a menu-driven application. Data Structures and Algorithms are integrated into the application rather than being treated as separate theoretical topics.
The project is designed for students who need to understand how programming concepts can solve real-world problems. Each operation is represented using an appropriate structure. For example, a queue is suitable for pending kitchen orders because the first order received is normally processed first. A stack is suitable for maintaining recently completed operations. Searching algorithms locate menu items, while sorting algorithms arrange menu records by price or name.


2. PROBLEM STATEMENT
Manual restaurant management can lead to duplicated entries, incorrect calculations, difficulty in locating menu items, and delays in processing orders. A computerized system should provide a simple way to manage menu records, customers, orders, tables, and bills.
The problem addressed by this project is the design and implementation of a Java application that can store restaurant information and process common restaurant operations using DSA. The system should be easy to operate, logically organized, and capable of producing clear outputs.

3. EXISTING SYSTEM
In a basic manual system, menu information may be maintained on printed cards, orders may be written on paper, and billing may be performed using a calculator. Although such methods can work for a small restaurant, they become difficult to manage when the number of customers and orders increases.
Typical disadvantages include manual calculation errors, difficulty tracking pending orders, slower searching, duplicate records, and limited reporting. Paper-based records can also be damaged or misplaced.
A computerized system reduces these problems by storing records in memory in a structured form. Operations can be performed through methods, and calculations can be handled automatically by Java. The academic version of this project does not attempt to replace a full commercial POS system; instead, it demonstrates the core logic required for such a system.

12. ALGORITHMS USED
The project demonstrates several algorithms.
Linear Search: Checks each menu item until the requested item is found. It is simple and suitable for a small menu.
Binary Search: Can be used when menu items are sorted by ID. It repeatedly divides the search interval into two parts.
Bubble Sort: Compares adjacent records and swaps them when they are in the wrong order. It is easy to understand and useful for demonstrating sorting concepts.
Insertion Sort: Builds a sorted section one element at a time. It performs well for small or nearly sorted lists.
Merge Sort: Uses divide and conquer and provides O(n log n) worst-case time.
Queue Processing: Enqueue adds an order to the rear, while dequeue removes the order from the front.
Stack Processing: Push adds a record to the top, while pop removes the most recent record.

17. QUEUE-BASED ORDER PROCESSING
A restaurant kitchen commonly handles orders in the sequence in which they arrive. This behavior maps naturally to a Queue.
Queue operations:
Enqueue – add a new order at the rear.
Dequeue – remove the order from the front.
Peek – view the first pending order without removing it.
isEmpty – check whether any order is pending.
Example:
Order 101 → Order 102 → Order 103
If the kitchen processes one order, Order 101 is removed first. Then Order 102 becomes the front item.
Java provides Queue and LinkedList implementations. For DSA learning, the queue behavior can also be implemented manually using an array and front/rear indexes.


18. STACK-BASED RECENT OPERATIONS
A stack follows Last-In-First-Out (LIFO). It is useful for storing recent completed order IDs or recent activities.
Example:
Push Order 101
Push Order 102
Push Order 103
The top is Order 103. A pop operation removes Order 103 first.
The stack demonstrates how a data structure can model application history. In an advanced version, the stack can support an undo mechanism. For example, if an administrator accidentally marks an order as completed, an undo operation could retrieve the last action from the stack and reverse it.

When a customer is seated, the selected table is marked occupied. When the customer finishes, the table is released.
The system should check table availability before assigning it. A simple linear scan can find the first available table with sufficient capacity.
Example:

This module demonstrates object state changes and searching through a collection.


20. BILLING MODULE
Billing converts an order into a payable amount. The subtotal is calculated by multiplying each item's price by its quantity.
Subtotal = Σ(price × quantity)
A tax percentage can then be applied:
Tax = Subtotal × TaxRate / 100
Discount can be applied when appropriate:
DiscountAmount = Subtotal × DiscountRate / 100
Final Amount = Subtotal + Tax − DiscountAmount
Example:
Subtotal = ₹500
Tax at 5% = ₹25
Discount = ₹20
Final Amount = ₹505
All monetary values should ideally be represented using BigDecimal in production systems. The educational implementation may use double for simplicity, while explaining that floating-point arithmetic has limitations.


21. SEARCHING
Searching is used to locate a food item or order.
Linear search examines records from the beginning until a match is found. If there are n records, the worst-case time is O(n).
Binary search requires sorted data. It compares the target with the middle element and discards half of the remaining search range. Its time complexity is O(log n).
For a small restaurant menu, linear search is often sufficient and easier to maintain. Binary search becomes more useful when records are sorted and the number of records is large.
The project can demonstrate both methods so that students can compare their behavior and complexity.


22. SORTING
Sorting improves the presentation and usability of menu data. Items can be sorted by price, name, category, or ID.
Bubble sort is easy to implement and explain but has O(n²) worst-case time. Insertion sort also has O(n²) worst-case time but can be efficient for nearly sorted data.
Merge sort uses divide and conquer. It divides the list, recursively sorts both halves, and merges them. Its time complexity is O(n log n).
For a college project, implementing Bubble Sort and Merge Sort provides a clear comparison between a simple quadratic algorithm and an efficient divide-and-conquer algorithm.


23. COMPLETE JAVA PROGRAM – PART 1
The following code provides the core model classes and uses Java collections for DSA-based storage.
import java.util.*;

class FoodItem {
    int id;
    String name;
    String category;
    double price;

    FoodItem(int id, String name, String category, double price) {
        this.id = id;
        this.name = name;
        this.category = category;
        this.price = price;
    }

    public String toString() {
        return id + "  " + name + "  " + category + "  " + price;
    }
}

class Order {
    int orderId;
    String customer;
    ArrayList<FoodItem> items = new ArrayList<>();
    ArrayList<Integer> quantities = new ArrayList<>();
    String status = "PENDING";

    Order(int orderId, String customer) {
        this.orderId = orderId;
        this.customer = customer;
    }

    void addItem(FoodItem item, int quantity) {
        items.add(item);
        quantities.add(quantity);
    }

    double total() {
        double sum = 0;
        for (int i = 0; i < items.size(); i++)
            sum += items.get(i).price * quantities.get(i);
        return sum;
    }
}


23. COMPLETE JAVA PROGRAM – PART 2
The following code continues the manager implementation and includes searching, sorting, queue processing, and billing.
class RestaurantManager {
    ArrayList<FoodItem> menu = new ArrayList<>();
    Queue<Order> pendingOrders = new LinkedList<>();
    Stack<Integer> completedOrders = new Stack<>();
    int nextOrderId = 101;

    void addFood(FoodItem item) {
        menu.add(item);
    }

    void displayMenu() {
        System.out.println("ID   NAME             CATEGORY       PRICE");
        for (FoodItem f : menu)
            System.out.printf("%-4d %-16s %-14s %.2f%n",
                    f.id, f.name, f.category, f.price);
    }

    FoodItem searchById(int id) {
        for (FoodItem f : menu)
            if (f.id == id) return f;
        return null;
    }

    FoodItem searchByName(String name) {
        for (FoodItem f : menu)
            if (f.name.equalsIgnoreCase(name)) return f;
        return null;
    }

    void sortByPrice() {
        menu.sort(Comparator.comparingDouble(f -> f.price));
    }

    Order createOrder(String customer) {
        Order o = new Order(nextOrderId++, customer);
        pendingOrders.offer(o);
        return o;
    }

    void processNextOrder() {
        if (pendingOrders.isEmpty()) {
            System.out.println("No pending orders.");
            return;
        }
        Order o = pendingOrders.poll();
        o.status = "COMPLETED";
        completedOrders.push(o.orderId);
        System.out.println("Processed Order: " + o.orderId);
    }

    void displayPending() {
        for (Order o : pendingOrders)
            System.out.println(o.orderId + " - " + o.customer);
    }

    double bill(Order o, double taxRate, double discount) {
        double subtotal = o.total();
        return subtotal + subtotal * taxRate / 100 - discount;
    }
}

public class RestaurantManagementSystem {
    public static void main(String[] args) {
        RestaurantManager r = new RestaurantManager();

        r.addFood(new FoodItem(1, "Idly", "Breakfast", 40));
        r.addFood(new FoodItem(2, "Masala Dosa", "Breakfast", 80));
        r.addFood(new FoodItem(3, "Veg Biryani", "Main Course", 160));
        r.addFood(new FoodItem(4, "Paneer Curry", "Main Course", 180));
        r.addFood(new FoodItem(5, "Fresh Lime", "Beverage", 50));

        System.out.println("RESTAURANT MANAGEMENT SYSTEM");
        r.displayMenu();

        FoodItem f = r.searchByName("Veg Biryani");
        if (f != null)
            System.out.println("Found: " + f.name + " - " + f.price);

        Order o = r.createOrder("Rahul");
        o.addItem(r.searchById(2), 2);
        o.addItem(r.searchById(5), 1);

        System.out.println("Order total: " + o.total());
        System.out.println("Final bill: " + r.bill(o, 5, 0));

        r.processNextOrder();
        System.out.println("Last completed order: " + r.completedOrders.peek());
    }
}


24. PROGRAM EXPLANATION
The FoodItem class stores menu information. Its constructor initializes the fields and its toString method produces a readable record.
The RestaurantManager class stores the menu using ArrayList. A Queue<Order> is used for pending orders, and a Stack<Integer> stores completed order IDs.
When addFood is called, a FoodItem is created and added to the menu list. The searchByName method performs a case-insensitive linear search. The sortByPrice method uses a comparator to arrange items in ascending order.
The createOrder method creates an order and adds it to the pending queue. The processNextOrder method removes the first pending order and pushes its ID to the completed stack.
This architecture demonstrates how Java classes and DSA structures work together rather than existing as isolated examples.

32. COMPLEXITY ANALYSIS
Let n be the number of menu items.
Linear search: O(n) time, O(1) extra space.
Binary search: O(log n) time after sorting, O(1) iterative space.
Bubble sort: O(n²) worst-case time.
Insertion sort: O(n²) worst-case time.
Merge sort: O(n log n) time and O(n) auxiliary space.
Queue enqueue/dequeue: O(1) for linked implementation.
Stack push/pop: O(1).
Displaying all menu items: O(n).
Complexity analysis explains why different structures and algorithms are selected. The goal is not only to make a program work, but also to understand how its performance changes as data size increases.
Operation	Time	Space

Bubble Sort	O(n²)	O(1)
Merge Sort	O(n log n)	O(n)
Queue enqueue	O(1)	O(1)

34. ALGORITHM – PROCESS ORDER
Step 1: Start.
Step 2: Check whether the pending queue is empty.
Step 3: If empty, display “No pending orders”.
Step 4: Otherwise remove the front order.
Step 5: Display the order details.

Step 7: Simulate completion.
Step 8: Change status to COMPLETED.
Step 9: Push the order ID onto the completed stack.
Step 10: Display confirmation.
Step 11: Stop.

Step 7: Calculate final amount.
Step 8: Display item-wise amounts.

40. LIMITATIONS
The basic console implementation has limitations. Data may be lost when the program terminates if no database is connected. There is no multi-user authentication, network communication, online payment integration, printer integration, or real-time kitchen display.
The console interface is suitable for learning but not as convenient as a graphical or web application. Using double for currency is acceptable for demonstration but not ideal for financial production software.
The system also assumes that users enter mostly valid data. A production system would require stronger validation, logging, security controls, database transactions, concurrency management, and backup mechanisms.

42. SECURITY CONSIDERATIONS
A production restaurant application should protect employee accounts and customer information. Passwords should never be stored as plain text. Access should be restricted according to user roles.
Input validation is also a security requirement. Database queries should use prepared statements to reduce SQL injection risk. Logs should avoid unnecessary exposure of sensitive information.
The academic console version does not implement full security because its primary purpose is learning Java and DSA. Nevertheless, understanding these requirements is important when moving from a classroom prototype to a real software system.

45. APPENDIX – FULL DEMONSTRATION CODE
Below is a compact complete demonstration program suitable for Eclipse or another Java IDE. It avoids external libraries and shows menu management, searching, sorting, queue processing, stack usage, and billing.
import java.util.*;

public class RestaurantDemo {
    static class Food {
        int id; String name; double price;
        Food(int id, String name, double price) {
            this.id=id; this.name=name; this.price=price;
        }
    }

    static ArrayList<Food> menu = new ArrayList<>();
    static Queue<String> orderQueue = new LinkedList<>();
    static Stack<String> history = new Stack<>();

    static Food search(int id) {
        for (Food f : menu)
            if (f.id == id) return f;
        return null;
    }

    static void sortByPrice() {
        menu.sort(Comparator.comparingDouble(f -> f.price));
    }

    public static void main(String[] args) {
        menu.add(new Food(1, "Idly", 40));
        menu.add(new Food(2, "Dosa", 80));
        menu.add(new Food(3, "Biryani", 160));

        System.out.println("MENU");
        for (Food f : menu)
            System.out.println(f.id + " " + f.name + " " + f.price);

        Food f = search(2);
        System.out.println("Search result: " + f.name);

        orderQueue.offer("Order-101");
        orderQueue.offer("Order-102");
        System.out.println("Processing: " + orderQueue.poll());

        history.push("Order-101 completed");
        System.out.println("Recent action: " + history.peek());

        sortByPrice();
        System.out.println("Sorted menu:");
        for (Food x : menu)
            System.out.println(x.name + " " + x.price);
    }
}
